# W8 — Frontend Unification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render one unified upload/history/session experience in `lap-website/` that consumes W1 contracts (`SessionContract`, `CoachingContract`, `OptimizerContract`), auto-scales depth via `session.capabilities.channels` + `optimizer.depth`, and never branches on `session.source` in render code.

**Architecture:** A capability-driven panel registry replaces source-specific UI code. Each panel declares the `ChannelTag[]` it requires and a stable `order`. A pure selector filters panels against the session's capabilities, then sorts — the view is a simple `.map()` over the filtered list. TS types come from `lap-website/src/types/contracts.ts` (auto-generated in W1.T1.4b — do not hand-edit). MSW with `NEXT_PUBLIC_USE_MSW=1` lets the frontend develop against authored fixtures while backend contract endpoints (W2/W3/W4) are still in flight; turning the flag off cuts the app over to live endpoints with zero code change.

**Tech Stack:**
- Next.js 14 App Router (Cloudflare Workers via OpenNext)
- TanStack Query 5 for contract fetching + caching
- TypeScript 5 types from `contracts.ts` (auto-generated)
- MSW (dev-only devDependency) for fixture-driven development
- Vitest 4 + @testing-library/react for unit + component tests
- Playwright 1.58 for E2E per-source smoke
- Design tokens from `src/styles/tokens.css` — `asphalt`, `concrete`, `chalk`, `steel`, `gold`, `acid-green`, `safety-red`, `marshal-yellow`, `racing-purple`
- Existing vanilla-JS chart-sync mechanism (`public/js/chart_sync.js` + `useVanillaChart` hook) — **preserved, not replaced**

## Panel Registry — Reference Code

```ts
// lap-website/src/lib/panel-registry.ts
import type { ComponentType } from 'react';
import type {
  ChannelTag,
  CoachingContract,
  OptimizerContract,
  SessionCapabilities,
  SessionContract,
} from '@/types/contracts';

export interface PanelContext {
  session: SessionContract;
  coaching: CoachingContract | null;
  optimizer: OptimizerContract | null;
}

export interface PanelSpec {
  id: string;
  component: ComponentType<PanelContext>;
  requires: ChannelTag[];  // empty = always eligible
  order: number;           // lower renders first
  label: string;           // for accessibility + dev tools
}

/**
 * Pure function — filters panels whose `requires` is a subset of the session's
 * available channels, then sorts by `order`. Never reads `session.source`.
 */
export function selectPanels(
  panels: readonly PanelSpec[],
  capabilities: SessionCapabilities,
): PanelSpec[] {
  const channels = new Set<ChannelTag>(capabilities.channels ?? []);
  return panels
    .filter((p) => p.requires.every((tag) => channels.has(tag)))
    .sort((a, b) => a.order - b.order);
}
```

**Why this shape:**
- `requires: ChannelTag[]` (not `requires: (ctx) => boolean`) keeps the selector pure and trivially testable; predicate-style gates move into the panel itself (e.g. "Optimizer depth is full_fidelity → show input trace").
- `order: number` (not insertion order) lets independent panels register themselves without racing.
- `component: ComponentType<PanelContext>` — every panel receives all three contracts; it picks what it needs. Avoids prop-drilling at the Host level.

## MSW — Fixture Strategy

**Source of truth:** authored TS fixtures in `src/mocks/fixtures/*.ts`, typed by the generated `contracts.ts`. TypeScript catches contract drift at compile time.

**Not** consuming W1's JSON fixtures directly (two reasons): they are Python-side fixtures under a different directory that may not travel into the frontend tree, and direct JSON import loses the discriminated-union narrowing that TS gives us on `SourceLiteral` and `OptimizerDepth`.

**Env toggle:**
- `NEXT_PUBLIC_USE_MSW=1` → the client-side bootstrap in `app/layout.tsx` imports `src/mocks/browser.ts` and calls `worker.start()`.
- Default (flag unset or `0`) → MSW is not loaded; real backend endpoints are used.

**Scope of handlers:** MSW only mocks the three new contract endpoints that W2/W3/W4 will eventually expose:
- `GET /api/v1/sessions/:id/contract` → `{ session, coaching, optimizer }` envelope.
- `GET /api/v1/sessions` (list) → includes `source` + `capabilities.channels` on each row.
- `POST /api/v1/sessions/upload` → returns `{ job_id, detected_source: 'real_life' | 'iracing' }` as part of the upload envelope.

Legacy endpoints (`/sessions/:id/laps`, `/sessions/:id/scores`, `/sessions/:id/corners`, `/jobs/:id/stream`) remain **unmocked** — they hit the real dev backend. This lets W8 ship independently of W2's routing work while keeping today's session detail page fully functional.

```ts
// lap-website/src/lib/session-contracts-client.ts
import { useQuery } from '@tanstack/react-query';
import { apiFetch } from './api-client';
import type {
  CoachingContract,
  OptimizerContract,
  SessionContract,
} from '@/types/contracts';

export interface SessionContractBundle {
  session: SessionContract;
  coaching: CoachingContract | null;
  optimizer: OptimizerContract | null;
}

function assertSessionContract(raw: unknown): asserts raw is SessionContract {
  const o = raw as Partial<SessionContract>;
  if (!o || typeof o !== 'object' || typeof o.session_id !== 'string' ||
      typeof o.source !== 'string' || typeof o.duration_s !== 'number' ||
      !o.capabilities || !o.driver || !o.track) {
    throw new Error('invalid session contract: missing required fields');
  }
}

export async function fetchSessionContract(sessionId: string): Promise<SessionContractBundle> {
  const bundle = await apiFetch<SessionContractBundle>(
    `/sessions/${encodeURIComponent(sessionId)}/contract`,
  );
  assertSessionContract(bundle.session);
  return bundle;
}

export function useSessionContract(sessionId: string) {
  return useQuery({
    queryKey: ['session-contract', sessionId],
    queryFn: () => fetchSessionContract(sessionId),
    staleTime: 30_000,
  });
}
```

```js
// lap-website/scripts/lint-source-branching.mjs
import { readdirSync, readFileSync, statSync } from 'node:fs';
import { join, extname, relative } from 'node:path';

const ROOT = new URL('../src', import.meta.url).pathname;
const EXCLUDE_SUFFIXES = ['.test.ts', '.test.tsx'];
const EXCLUDE_DIRS = ['mocks', '__tests__'];
const EXCLUDE_FILES = ['types/contracts.ts'];

const PATTERN = /session\.source\s*[=!]==|\.source\s*[=!]==\s*['"](real_life|iracing|ac)['"]/;

function* walk(dir) {
  for (const name of readdirSync(dir)) {
    const full = join(dir, name);
    const st = statSync(full);
    if (st.isDirectory()) {
      if (EXCLUDE_DIRS.includes(name)) continue;
      yield* walk(full);
    } else {
      yield full;
    }
  }
}

const violations = [];
for (const file of walk(ROOT)) {
  const rel = relative(ROOT, file).replace(/\\/g, '/');
  if (EXCLUDE_FILES.some((p) => rel === p)) continue;
  if (EXCLUDE_SUFFIXES.some((s) => rel.endsWith(s))) continue;
  if (!['.ts', '.tsx'].includes(extname(file))) continue;
  const content = readFileSync(file, 'utf-8');
  content.split('\n').forEach((line, i) => {
    if (PATTERN.test(line)) violations.push(`${rel}:${i + 1}: ${line.trim()}`);
  });
}

if (violations.length) {
  console.error('[lint:source-branching] Forbidden source branching in render code:');
  for (const v of violations) console.error('  ' + v);
  console.error('\nUse `session.capabilities.channels` or `optimizer.depth` instead.');
  process.exit(1);
}
console.log('[lint:source-branching] OK — no source branching in render code');
```
